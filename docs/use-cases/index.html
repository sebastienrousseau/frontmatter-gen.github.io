Static Site Generators & Documentation Portals

Static site compilers frequently ingest thousands of Markdown pages authored across different eras or migrated from Hugo (TOML +++), Jekyll/Astro (YAML ---), or headless CMS exports (JSON { ... }). frontmatter-gen normalizes all three into a single Frontmatter type and synthesizes escaped HTML <meta> tags:

Pipeline Capability Legacy Regex / YAML 1.1 Stack Frontmatter Gen Engine
Supported Header Formats Separate crates per format Unified YAML 1.2, TOML 1.1 & JSON in one crate
YAML 1.1 Norway Problem Unquoted NO / off coerced to booleans Strict YAML 1.2 preserves unquoted strings via noyalib
Body Slicing Overhead Allocates new String copies of Markdown body Zero-copy borrowed &str via extract_raw_frontmatter
SEO Meta Tag Generation Manual string concatenation prone to unescaped quotes Built-in entity-escaped meta::generate_metatags
rust — static site page compiler
use frontmatter_gen::{extract, meta::generate_metatags};
 
pub fn compile_page(source: &str) -> Result<(String, &str), Box<dyn std::error::Error>> {
    let (frontmatter, markdown_body) = extract(source)?;
    let head_meta_tags = generate_metatags(&frontmatter)?;
    Ok((head_meta_tags, markdown_body))
}
02

Multi-Tenant Content APIs & Untrusted Upload Guardrails

When accepting user-authored Markdown files over HTTP or webhook integrations, ParseOptions bounds recursion depth and total key counts before application logic runs:

rust — untrusted webhook ingestion
use frontmatter_gen::extractor::{detect_format, extract_raw_frontmatter};
use frontmatter_gen::parser::{parse_with_options, ParseOptions};
 
let (raw, body) = extract_raw_frontmatter(untrusted_markdown)?;
let budget = ParseOptions { validate: true, max_depth: Some(6), max_keys: Some(50) };
let verified_fm = parse_with_options(raw, detect_format(raw), &budget)?;
03

CI/CD Documentation Linters & Cross-Format Migration

Use the standalone fmg CLI in GitHub Actions or pre-commit hooks to validate that every Markdown document in a repository contains well-formed frontmatter and convert legacy TOML headers into JSON or YAML:

bash — ci frontmatter validation & conversion
# Validate and convert a TOML-header Markdown file's frontmatter to JSON
$fmg extract docs/guide.md --format json --output /tmp/guide-meta.json
Unified document metadata: ingest YAML 1.2, TOML 1.1, and JSON frontmatter across library, CLI, and static site pipelines.
